# UWScan2 Git 规范

更新日期：2026-09-14

本规范用于保持 UWScan2 的源码、资源和构建配置可追溯，同时避免把本机
缓存、编译输出和设备环境文件混入提交。

## 应提交的内容

下列路径承载项目可复现的源码或配置，应随功能改动一并提交：

- `src/`：C++ 实现。
- `include/`：公开头文件。
- `resources/`：界面文件、资源清单、图标和图片。
- `cmake/`：自定义依赖查找模块。
- `lib/`：项目明确依赖并随仓库分发的第三方头文件、库和 DLL。
- `python/`：Python SDK 和 `requirements.txt`。
- `examples/`、`scripts/`：经验证的示例与辅助构建脚本。
- `docs/`：与当前实现一致的维护文档。
- `CMakeLists.txt`、`CMakePresets.json`、`.gitignore`、`README.md` 等顶层配置。

## 不应提交的内容

以下内容由工具生成、仅服务于本机环境，或可由源码重新生成：

- `.vs/`、`build/`、`build-uwscan3d-algorithms/`、`out/`。
- `CMakeCache.txt`、`CMakeFiles/`、`*_autogen/`。
- `Debug/`、`Release/`、对象文件、PDB、ILK、EXP 和临时日志。
- `python/**/__pycache__/`、`*.pyc`。
- 本机设备采集结果、未脱敏的标定数据、临时导出点云和屏幕截图。

`bin/` 是当前可运行发布目录，通常不作为源码提交对象；若需要发布版本，
应通过发布包、版本标签或专用交付渠道管理，而不是把每次本机构建结果混入
功能提交。

## 分支与提交

- 一个提交只处理一个清晰目标，例如“修复 TCP 超时”或“新增点云滤波器”。
- 提交前确认没有把无关格式化、缓存文件或本机路径带入变更。
- 新功能应同时提交实现、必要的头文件、资源、CMake 引用和最小验证说明。
- 修改公共协议、Python 接口或模块边界时，同步更新相应 `docs/` 文档。
- 对硬件相关改动，在提交说明中写明已验证的相机、运动控制器或模拟环境。

推荐格式：

```text
<模块>: <简短动作描述>

<需要时补充变更原因、兼容性或验证方式>
```

示例：

```text
scanner: 修复连续采集停止后的线程退出
pointcloud: 增加体素下采样入口
server: 校验命令帧长度
```

## 合并前检查

1. 检查 `git status --short`，确认每项变更都属于当前任务。
2. 检查 `git diff --check`，排除尾随空格和冲突标记。
3. 使用目标 CMake 预设完成至少一次配置；改动 C++ 或资源时再完成构建。
4. 改动 GUI 时验证主窗口能打开，相关界面文件能由 AUTOUIC 生成。
5. 改动扫描、Pylon、串口或 TCP 代码时，在可用硬件或明确的模拟条件下验证。
6. 改动 Python 包时，至少验证目标模块可被导入。

## 处理本机配置

- 机器相关的 SDK 路径优先放入 CMake 缓存、环境变量或
  `CMakeUserPresets.json`，不要把个人目录硬编码到新源码中。
- 新增第三方依赖时，记录版本、来源和部署要求；若随仓库分发，更新 `lib/`
  和对应的 CMake 查找脚本。
- 清理 `build/` 或 `.vs/` 前无需提交，它们会在下次配置或打开工程时生成。

## 禁止操作

- 不要用 `git reset --hard`、`git checkout --` 等方式覆盖未确认的本地工作。
- 不要因整理目录而删除 `lib/`、`resources/` 或 `bin/` 中未经过依赖验证的文件。
- 不要提交密码、设备账号、内网地址、绝对用户目录或未经确认的客户数据。
